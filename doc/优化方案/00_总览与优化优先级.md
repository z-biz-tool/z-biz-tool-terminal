## 0.1 一句话定位与关键事实澄清

z-terminal 的真实形态是 **基于 Tauri 2 + React 19 + russh 的「远程 SSH/SFTP 终端管理器」**（对标 Xshell/Tabby/Termius），而**不是**本地 shell/PTY 终端。

调研中最重要的一个事实澄清（贯穿全部文档）：

- 代码中**不存在本地 PTY / 本地进程派生**。`src-tauri/src/lib.rs` 注册的全部命令都是 SSH/SFTP/端口转发/配置类，没有任何 `pty_spawn`/`Command::new(shell)` 之类的本地终端后端（唯一 `std::process::Command` 出现在 `open_file_with_default_app`，用于「用系统默认程序打开文件」，与终端无关）。
- 所有「PTY」实为 **russh 的远程交互式 shell 通道**：`ssh.rs::start_pty` 通过 `channel.request_pty(... "xterm-256color" ...)` + `request_shell` 在**远端服务器**上开 shell，前端 xterm.js 渲染。
- 因此任务书中「PTY 后端与跨平台（macOS/Windows 差异）」「本地进程管理」等命题需**重定向**为：跨平台差异体现在 **Rust SSH 客户端行为、Tauri WebView、文件路径/打开方式**，而非本地 conhost/pty 分配。本方案据实调整，不编造本地 PTY 能力。

> 参见证据：[lib.rs 命令注册](../../src-tauri/src/lib.rs#L12-L52)、[start_pty 远程 shell](../../src-tauri/src/ssh.rs#L491-L612)。

## 0.3 终端工具的独特价值（为什么值得单独优化）

1. **它是「高危操作的执行入口」**：不同于笔记/文件类工具，终端每条命令都可能不可逆（`rm`、`dd`、`shutdown`、批量下发）。安全边界是第一价值，不是附加项。
2. **它是「凭证的集中地」**：SSH 密码、私钥、跳板机链路、AI API Key 全部在此汇聚，一旦泄漏影响面极大。
3. **它是「高频实时 IO 场景」**：`cat` 大文件、`yes`、日志 `tail -f` 会产生每秒数千次输出事件，渲染与 IPC 背压直接决定可用性。
4. **它已具备真实 SSH 全栈能力**（russh PTY/SFTP/三种端口转发/跳板机/密钥生成），底座扎实，优化重点是「把已宣称但半成品/死代码的能力补齐，把安全与性能短板补上」，而非重写。

## 0.4 核心原则（跨文档一致性约束，务必遵守）

以下 4 条为全套方案的不可妥协底线，02/03/04/05/06 均以此为准：

- **P-1 AI 不得自动执行破坏性命令**：AI（自然语言转命令、多智能体、聊天）产出的任何命令**只能填充/建议**，落地到 PTY 前必须经用户显式确认；破坏性命令永不自动执行。当前 `AINaturalLanguageCommand` 的「发送到终端」实际是 no-op（见 01），修复时必须内置该原则，而非简单接通。
- **P-2 危险命令需二次确认**：无论来自用户手输、Snippet、批量执行还是 AI，命中危险模式的命令必须弹出确认（展示将影响的会话/主机清单）。
- **P-3 会话隔离**：每个 tab/pane 的 SSH 会话、PTY 通道、日志文件、端口转发互相隔离；一个会话的长命令/断开/重连不得阻塞或污染其它会话（当前全局单 Mutex 违反此原则，见 01/03）。
- **P-4 密钥/环境不泄漏到日志**：会话日志、错误信息、AI 上下文、配置导出中不得出现明文密码/私钥/API Key；日志需可脱敏、可关闭、可加密。

## 0.6 分阶段能力演进（概览，详见 05）

- **阶段一（P0 止血）**：安全红线 6 项 + 并发阻塞修复。目标：可安全对外使用。
- **阶段二（诚实化 AI）**：把「宣称但未落地/半成品/死代码」的 AI 能力要么补齐要么下线，消除文档与实现的落差（命令解释/错误分析不可用、多智能体不可用、Cloud Agent 是 mock、聊天非流式且停止无效、配置不持久化）。目标：AI 能力真实、可信、符合 P-1。
- **阶段三（性能与体验）**：输出批处理与背压、渲染加速、会话隔离重连、批量执行独立通道。目标：高频输出不卡顿、多会话不互相干扰。
- **阶段四（可靠性与工程化）**：测试矩阵落地、CI 增加 typecheck/lint/test job、崩溃恢复、日志治理。目标：可回归、可度量。
- **阶段五（增强，可选）**：本地终端后端（若产品确需）、known_hosts 管理 UI、审计导出、profile/环境管理。目标：对标 iTerm2/Warp/Windows Terminal 理念（不复制其代码、不编造竞品实时事实）。

## 0.7 量化验收目标（摘要，完整 12+ 项见 06）

> 所有指标均为**拟定验收目标**，非现状实测；标注了假设。

1. 主机公钥首次连接需用户确认，known_hosts 命中率 100%（假设：新增 known_hosts 存储）。
2. 诊断/执行类命令注入用例 0 通过（全部被转义/拒绝）。
3. 单个长命令执行期间，其它标签键入到回显延迟 < 50ms（当前：全程阻塞）。
4. 配置文件权限 0600；明文凭证字段数 = 0（迁移到系统钥匙串或加密）。
5. 会话日志中密码/私钥/API Key 明文出现次数 = 0（脱敏规则覆盖）。
6. 危险命令确认覆盖率 100%（手输/Snippet/批量/AI 四入口）。
7. AI 生成命令自动执行次数 = 0（P-1）。
8. `cat` 100MB 文本时前端不冻结，IPC 事件数较现状下降 ≥ 80%（批处理，假设 16ms 合并窗口）。
9. AI 聊天首字节可见时间 < 1.5s（真流式，假设网络正常）。
10. 分屏多 pane 断线后全部自动恢复（当前仅 pane[0]）。
11. 重连采用指数退避，稳态失败重试频率 ≤ 1 次/30s（当前固定 3s 无限）。
12. 单元测试 + 集成测试覆盖核心后端模块，CI 阻断式运行（当前 0 测试）。
